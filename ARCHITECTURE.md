## 2. The Core Invention: The Dynamic Q2S2V Extraction Engine

The fatal flaw in modern AI is the "**Column Explosion**" and the "**Tribal Knowledge Gap**." SYNAPSE executes a strict, 4-stage Just-In-Time (JIT) Mathematical Reduction Funnel that shrinks 15,000 tables and millions of columns down to exactly the pristine payload needed in <500 milliseconds.

### 🌟 Phase A: The Self-Healing Ontology Graph (Macro-Pruning & Tribal Routing)
Instead of relying on static Vector Databases that break when schemas drift, or raw query logs that violate PII, we build an **Active Semantic Knowledge Graph** natively anchored to Oracle’s structural metadata.

*   **Pillar 1: The Deterministic Skeleton:** We map Oracle FaaS into a strict mathematical Property Graph. Nodes are extracted instantly from `DBA_TABLES` and `DBA_TAB_COMMENTS`. Edges are hardwired using `DBA_CONSTRAINTS` (Foreign Keys). The AI is mathematically restricted to traversing only paths that physically exist.
*   **Pillar 2: The Autonomous Observer:** An asynchronous Observer Agent monitors Oracle's `V$SQLAREA`.
    *   **The InfoSec Bypass:** It strictly reads Parameterized Execution Plans (e.g., `WHERE tenant_id = :B1`). It never sees literal PII values.
    *   **Tribal Knowledge Extraction:** It mines ASTs for statistical patterns (e.g., "98% of queries joining `POD_INVENTORY` with `PATCH_LOGS` explicitly filter out `is_test_pod = 'Y'`"). It autonomously writes these rules back into the Graph.

### ⚡ Phase B: O(1) CBO Telemetry Pruning (Meso-Pruning)
We now have 10 tables from Phase A, but they contain 8,000+ columns. How do we find the exact active columns without metadata?

*   **The Mechanism:** An Autonomous Scout Agent queries Oracle's live internal **Cost-Based Optimizer (CBO)** statistics (`DBA_TAB_COL_STATISTICS`).
*   **The Math:** It calculates a Column Utility Score $U(c)$ in $O(1)$ time:
    $$U(c) = \alpha \cdot \text{UsageFreq}(c) + \beta \cdot (1 - \frac{\text{NullCount}(c)}{\text{TotalRows}}) + \gamma \cdot \text{ShannonEntropy}(c)$$
*   **The Result:** The agent mathematically drops all abandoned columns and 99% NULL legacy columns. It uses Shannon Entropy to find columns with rich operational distributions, collapsing 8,000 cryptic columns to the 5 exact active columns.

### 🎯 Phase C: Distance-Bounded Value Grounding (Micro-Pruning)
Users ask for values that don't match database strings (e.g., "East Coast" vs. `US_EAST_1`).

*   **The Math:** Before generating SQL, the AI hashes the user's filter against an active Data Profile (Bloom Filter) on the Graph Node. If it misses, it fuses Cosine Similarity and Levenshtein Distance to snap the human word to the exact database ENUM.
*   **The Result:** It is mathematically impossible for the AI to hallucinate a WHERE clause that returns 0 rows.
